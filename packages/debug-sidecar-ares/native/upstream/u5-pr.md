# sfc: stop RSP sessions at coherent desktop execution boundaries

Based on the register and safe-memory contributions, defer the initial RSP stop response until the SNES CPU reaches an instruction boundary. A socket connection alone keeps the first instruction held. While halted, yield through the desktop worker so UI operations remain serviceable. WAI/STP also expose quiescent boundaries for interruption and reset without firing an execution breakpoint at the following PC.

Continue/step can leave the current breakpoint once and stop on its next execution. Add `monitor reset`, `reset halt`, and `reset run`, following the vocabulary in [#1792](https://github.com/ares-emulator/ares/issues/1792). Reset-halt responds only at the reset-vector boundary. Preserve the independent desktop pause state and disable runahead while a debugger client is connected. Other cores retain their existing stop contract unless they opt in.

Saving or loading while stopped must also yield a serialization safe point. Loading first creates an undo snapshot, which previously looped forever in the GDB stop. Preserve the halted CPU's registers/clocks during synchronization and refresh the stopped PC after load so stepping leaves a restored breakpoint once. This correction and its tests are in the final `U5-states` layer of the prepared series and must be included with this contribution.

Validation: native CTest checks pass against the actual server and SFC core on macOS arm64. Six state cases cover save/load/undo at instruction, WAI, and STP boundaries in both PPU modes, including the thread handoff used for desktop state operations. All six reproduce the original hang with a bounded failure guard. Release assertions are enabled after nall headers. The earlier desktop build passed synthetic-ROM attach, exact steps, repeated breakpoint, stopped-state packet round trips, Ctrl-C, WAI/STP, reset, reconnect, and GUI quit. That historical result does not test the new save-state fix. These are 65816-aware RSP checks. Additional clients and Linux/Windows remain before runtime promotion.

Configure `ARES_BUILD_OPTIONAL_TARGETS=ON` and build/run these tests with `tests/gdb/run-tests.sh /absolute/path/to/build`. The launcher uses CMake/CTest and ares's existing toolchain. Node is not required.
